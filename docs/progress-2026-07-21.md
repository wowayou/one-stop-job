## 北极星（已对齐）

**手机发链接 / 文本 / 截图 → 后端自动抽取 → 写入本地聊天候选 → 本人在 Web 勾选确认后才入库。**

- 不自动投递、不自动给招聘方发消息（CLAUDE.md 红线 §2）。
- Telegram 只是传输层，不是 `Job.source`。
- 入库**不是**默认行为；不值得留的岗位可以跳过，原文/截图仍留在聊天里。

## 关键决策（不要推翻除非产品改口）

1. **入库必须用户点确认** — 不是评分门槛自动过滤，也不是 AI `worth_storing`。
2. **原料进聊天，不进 Draft 表** — Draft 仍是话术/简历草稿；候选挂在 `metadata_json.candidates`。
3. **Telegram = 传输层** — `Job.source` 仍是公众号 / beBee / `manual`（`ingest.manual_source`）。
4. **链接不是唯一事实源** — BOSS 等抓不到时，用文本/截图 + LLM freeform。
5. **不自动对外消息** — 仅允许给机主本人的 Telegram 回执（§2 例外已写入 CLAUDE.md）。
6. **不做 token 流式** — 决策结果是结构化 JSON 卡片；用分阶段进度即可。
7. **多设备互连 / 暴露后端推迟** — 长轮询不需要。
8. **context_repo 不搞双 env 别名** — 只加强自检；路径按**当前运行环境**写绝对路径。
9. **公开仓库隐私** — `.env` / `data/` / 真实 SQLite 不进 Git；推送前检查 ignore。
