# 匹配评分与排序审计

## 当前评分输入

评分函数：`backend/app/services/scoring.py::score_job`

权威边界：`FitScore.total`、`hard_blocked` 和 `details.dimensions.*.score` 只由该规则函数产生。AI 只允许做岗位抽取、证据摘要、解释文本、核心优势话术、沟通草稿或对应简历，不直接写入或覆盖规则评分。

输入：

- `Job`：岗位标题、公司、技能、JD、经验、学历、地点、薪资、招聘人。
- `Company`：公司风险等级等画像。
- `ResearchItem[]`：公司调研证据、情绪、摘要。
- `UserProfile`：目标岗位、目标城市、薪资期望、技能、优势、排除项、权重。

## 当前评分维度

总分 100，默认权重：

| 维度 | 权重 | 说明 |
|---|---:|---|
| `role_match` | 25 | 岗位标题 / JD / 技能与目标岗位、个人技能关键词匹配 |
| `salary_city` | 15 | 薪资区间和目标城市匹配 |
| `growth` | 15 | 增长、出海、独立站、SEO、数据、跨境等成长关键词与正向证据 |
| `stability` | 15 | 公司风险等级和负面证据修正 |
| `reputation` | 10 | 调研证据中的口碑倾向 |
| `commute_rest` | 10 | 双休、不加班、弹性、通勤等生活质量信号 |
| `interview_roi` | 10 | 准备投入与岗位收益估计 |

## 硬阻断

命中以下条件时，`hard_blocked = true`，总分乘以 `0.55`：

- 城市不在目标范围。
- 薪资上限低于最低期望。
- 命中个人画像里的硬性排除项。

## 当前排序

后端冲刺包排序：

1. 非硬阻断优先。
2. 总分高优先。
3. 收藏岗位作为同分补充排序。

前端匹配评分队列已收敛为同一方向：

1. 非硬阻断优先。
2. 总分高优先。
3. 收藏岗位优先。
4. 新入库岗位作为最后补充排序。

## 已发现并处理

- 原前端排序只按总分降序，没有把硬阻断岗位后置；已修正。
- 原评分页个人画像和排序队列高度不一致，排序队列会拖长整页；已改为两侧同高、内部滚动。
- 顶部“高潜岗位 / 最高分”指标已可跳转到匹配评分视图。

## 风险与改进建议

1. 关键词匹配仍偏朴素。
   - 当前是包含匹配，不做同义词、语义归一或岗位别名。
   - 后续可增加本地同义词表，如 `SEO = 搜索优化 = 网站优化`。

2. 城市硬阻断可能过硬。
   - 远程、混合办公、跨区可接受场景可能被误伤。
   - 后续可把“城市不匹配”从硬阻断改为强扣分，或增加 `remote_ok` 字段。

3. 公司调研证据不足时默认分偏中性。
   - 没证据不等于好公司。
   - 后续可在排序队列里显示“证据不足”提示，引导补调研。

4. 画像更新后历史评分不会自动重算。
   - 这是当前 README 明确说明的行为。
   - 后续可在保存画像后提供“重算全部可行动岗位”按钮。

5. 薪资解析不覆盖所有表达。
   - 例如日薪、年薪、底薪+提成、面议目前只能部分表达。
   - 后续扩展 `parse_salary` 测试样例后再改。
