# job-one-stop v0.3.0

这是「升级体验版」：在应用内解决“不知道有新版本”这个问题，同时把发布产物做得可校验。

本版只做**升级发现**——检查、提示、打开对应平台的下载页。应用不会自己下载、替换或重启自己；
应用内一键更新需要代码签名与 updater 公钥，留到后续版本。

## 本版重点

- 设置 → 关于：显示当前版本、本机平台/架构、最近检查时间和更新状态（已是最新 / 有新版本 / 无法连接 / 检查失败）。
- 手动「检查更新」随时可点；启动时静默检查一次，失败不影响主流程。
- 检查结果本地缓存（默认 6 小时），手动检查绕过缓存；离线时明确显示“无法连接更新服务”，不会误报“已是最新”。
- 只识别正式 Release，忽略 Draft 与 Pre-release；版本按语义版本比较（`0.10.0` 高于 `0.9.0`）。
- 发现新版本后可查看发布说明，并直接打开与本机架构匹配的安装包下载地址。
- 升级后首次启动显示「本版新增」说明，同时列出升级不会改动的东西。
- AI「测试连接」发请求前先说明会真的调用一次接口、可能产生极低额费用、将使用哪个 Provider 与模型；
  成功后显示**实际命中**的那张 Provider 卡、模型、延迟，以及是否发生了备用切换。
- 版本号收敛到仓库根目录的 `VERSION` 单一事实源，由 `scripts/sync_version.py` 同步到
  `frontend/package.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json`
  和 `backend/app/version.py`；测试会锁住一致性。
- 发布流水线为每个安装包生成 `.sha256` 校验文件与按平台汇总的 `SHA256SUMS-<平台>.txt`。

## 安装包与架构对应

| 平台 | 架构 | 文件 |
|---|---|---|
| Windows | x64 | `*_x64_*.msi` / `*_x64-setup.exe` |
| macOS | Apple Silicon | `*_aarch64.dmg` |
| macOS | Intel | `*_x64.dmg` |
| Linux | x64 | `*_amd64.AppImage` / `.deb` / `.rpm` |

下载后可核对校验和：`sha256sum -c <安装包名>.sha256`（macOS 用 `shasum -a 256 -c`）。

## 安全边界

- 不自动投递。
- 不自动向招聘者发送消息。
- 不绕过验证码、风控页或平台限制。
- 升级检查只向 GitHub 公开 Releases 接口发一次只读请求，不携带任何本地数据；
  在 `config.yaml` 的 `updates.enabled` 置 `false` 即完全关闭。
- AI Key 只从本机 `.env` 读取，界面与接口一律只回“已配置 / 未配置”。

## 升级说明

- 无数据库迁移。
- 默认仍为“手动 + 核心”，升级不会自行开启自动驾驶。
- 个人画像、评分权重、岗位状态、已排除岗位和个人看板都不会被改动。
- `.env` 与 `config.yaml` 不会被覆盖；`updates` 段缺失时按内置默认值工作（启用检查、6 小时缓存）。

## 安装说明

- Windows：下载 `.msi` 或 `.exe`，双击安装。
- macOS：下载对应架构 `.dmg`，拖入 Applications；首次打开可右键选择“打开”。
- Linux：下载 `.AppImage`，添加执行权限后运行；也可使用 `.deb` 或 `.rpm`。
  Linux 本版只提供“发现更新 + 打开下载页”，不做原地自动升级。

本版本安装包未做商业代码签名。操作系统提示未知开发者时，请按系统流程确认后继续。
