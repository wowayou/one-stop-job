# 发布验收清单（每次发版跑一遍）

自动化能覆盖的部分已经在 `scripts/quality_gate.sh` 和 CI 里；这份清单只列**必须在真实机器上
用手验的**项目——跨平台安装、升级保数据、以及点击类交互。打包机不是使用机，装完能开 ≠ 升级没丢东西。

打勾前先确认：CI 的 release workflow 全绿、草稿 Release 里四个平台的安装包和 `.sha256` 都在。

## 1. 安装包与校验和

- [ ] 草稿 Release 里存在四套产物：Windows x64（`.msi` / `-setup.exe`）、macOS Apple Silicon（`*_aarch64.dmg`）、macOS Intel（`*_x64.dmg`）、Linux x64（`.AppImage` / `.deb` / `.rpm`）
- [ ] 每个安装包旁边有同名 `.sha256`，另有按平台汇总的 `SHA256SUMS-<平台>.txt`
- [ ] 至少抽一个包核对校验和：`sha256sum -c <包名>.sha256`（macOS 用 `shasum -a 256 -c`）
- [ ] Release 正文来自 `docs/releases/v<版本>.md`，不是上一版的文案

## 2. 应用内升级发现（本机就能验）

- [ ] 设置 → 关于：当前版本与刚发布的版本号一致
- [ ] 点「检查更新」→ 状态是「已是最新」（刚发完），最近检查时间刷新
- [ ] 断网后点「检查更新」→ 显示「无法连接更新服务」，**不能显示「已是最新」**
- [ ] 有新版本时：能看发布说明，「下载 <平台> 安装包」打开的是**本机架构**对应的那个包
- [ ] 「打开发布页」「SHA-256 校验文件」能在系统浏览器里打开（桌面端走 `shell:allow-open`）
- [ ] 升级安装后首次启动弹出一次「本版新增」，关掉后再启动不再弹

## 3. 升级保数据（最容易出事的一项）

在**已有数据**的机器上升级，而不是干净机器：

- [ ] 岗位池条数、状态分布与升级前一致
- [ ] 个人画像、评分权重没变
- [ ] `.env` 里的 AI Key 仍然生效（设置 → AI 显示「已配置」，测试连接通）
- [ ] `config.yaml` 没被覆盖：自动驾驶仍是升级前的模式，**没有被自行打开**
- [ ] 已排除 / 已跳过的岗位没有回来
- [ ] 个人看板（Obsidian）没有被自动改动
- [ ] 聊天线索与附件都还在

## 4. 分平台细节

**Windows x64**

- [ ] `.msi` 覆盖安装后数据保留（数据在 `data/`，不在安装目录，但要实测确认）
- [ ] 已有 `:8000` 服务在跑时启动桌面版：桌面版用自己的动态端口，**不会误连那个实例**
- [ ] 退出应用后后端子进程一起退出（任务管理器里没有残留 `job-one-stop-backend.exe`）

**macOS**

- [ ] Apple Silicon 机器下载到 `aarch64` 包，Intel 机器下载到 `x64` 包（别互换）
- [ ] 未签名首次打开：右键 →「打开」能通过，提示文案与安装说明一致
- [ ] 升级（拖入 Applications 覆盖）后数据保留

**Linux x64**

- [ ] `.AppImage` `chmod +x` 后能运行
- [ ] 本版**不做**原地自动升级：只验「发现更新 + 打开下载页」这条路径
- [ ] `.deb` / `.rpm` 走系统包管理器升级后数据保留

## 5. 诊断与失败恢复

- [ ] 设置 → 诊断能打开，`.env` 一侧只显示变量名与「已配置 / 未配置」，**没有任何值**
- [ ] 监听端口显示正确（桌面端是本次启动动态分配的那个）
- [ ] 「打开数据目录」在桌面端能唤起文件管理器；浏览器里退回复制路径
- [ ] 「备份数据」在 `data/backups/<时间戳>/` 生成可读的 `job_one_stop.sqlite3`，既有备份没被覆盖
- [ ] 「复制脱敏日志」粘出来的内容里**没有** API Key、没有 Telegram token
- [ ] 「重置本地缓存」后岗位/公司/聊天数据一条不少，只是引导重新出现

## 6. 出站边界复核（每次都要看）

- [ ] `updates.enabled=false` 时应用完全不请求 GitHub
- [ ] 诊断页的「网络连接状态」没有发起任何新请求（只汇总已有信号）
- [ ] 没有任何自动投递、自动给招聘方发消息的行为
