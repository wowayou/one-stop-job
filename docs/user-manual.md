# 用户操作手册

这是一套本地优先的求职工作台。推荐的使用顺序是：

```text
校准画像 → 手动扫描一轮 → 聊天确认候选 → 入库 → 调研/准备 → 记录行动 → 跟进收口
```

系统不会自动投递、不会自动私信招聘者，也不会替你移动岗位看板。自动驾驶只负责本地搜集、去重、分类、评分和准备材料，最终确认仍由你完成。

## 1. 第一次打开

### 1.1 启动

日常使用推荐单进程模式：

```bash
scripts/app.sh start
```

浏览器打开 `http://127.0.0.1:8000/`。Windows 无 WSL 时使用 `start_app.bat` 或 Docker 方式，详见 [QUICKSTART.md](../QUICKSTART.md)。

首次进入会看到“开始使用”检查卡。它会检查个人画像、BOSS 采集、AI 和当前自动驾驶模式。先不要急着打开自动驾驶，先把手动闭环跑通。

### 1.2 填写个人画像

进入“设置 → 个人画像”，至少填写：

| 字段 | 怎么填 |
|---|---|
| 目标岗位 | 用你真正愿意投的岗位名，例如 `SEO运营、英文网站运营` |
| 目标城市 | 填 `青岛`、`青岛/远程` 等真实接受范围 |
| 最低/最高 K | 填底线和可接受上限；不要为了扩大结果而降低底线 |
| 技能 | 填真实掌握的工具、工作方法和语言能力 |
| 优势 | 填可以在面试中举证的成果，不要写愿望 |
| 实际工作经历 / 项目成果 | 只写正式经历和可核验项目，培训不要包装成正式经验 |
| 排除项 | 填纯销售、纯投流、单休、低于底薪等明确不要的条件 |
| 通勤偏好 | 填远程、通勤上限、可接受区域等 |

点击“保存画像”。画像会影响评分、硬拦截、候选建议和材料准备。

### 1.3 检查 BOSS 采集

进入“设置 → 采集来源”，查看 BOSS 状态：

- `可运行`：可以扫描。
- `需要宿主机导入`：需要在 Windows 宿主机运行 OpenCLI 脚本，再回到应用导入结果。
- `未配置 / 错误`：先检查 `config.yaml` 中的 `opencli.boss_cmd`、关键词和城市，以及 OpenCLI 登录态。

首次推荐保持：

```yaml
automation:
  mode: manual
reach:
  level: core
```

## 2. 跑通第一轮

1. 首页顶部保持“自动驾驶：关”“求职面：核心”。
2. 点击“立即扫描”。
3. 等待扫描完成，查看“发现、硬拦截、待确认”数量。
4. 打开左侧“聊天”，进入最新的“采集 · BOSS直聘”线索。
5. 展开候选卡，重点看：匹配分、岗位族、相邻度、能力重合、必要条件缺口、风险问题和材料包。
6. 只勾选你愿意继续判断的候选，点击“入库选中”。
7. 没有勾选的岗位会保留在聊天线索中，不会进入岗位池；硬阻断岗位默认折叠，也不会默认勾选。

### 扫描数字怎么看

- **发现**：本次来源返回的原始岗位数。
- **硬拦截**：命中城市、薪资、排除项等硬条件的岗位数。
- **待确认**：仍等你在聊天里判断的候选数。
- **材料包**：已准备本地简历版本、投递理由和风险问题的候选数。

过滤掉的岗位不会静默消失。采集运行记录和聊天摘要会保留区域过滤、低于分数线、超出单次上限等计数及样例。

## 3. 入库后的日常工作

### 岗位池

在“岗位”里按分数或状态筛选岗位。打开岗位抽屉后：

- 刷新评分，确认硬条件和各维度解释。
- 补公司官网、招聘页、搜索、小红书、脉脉或手动笔记证据。
- 生成面试准备，查看 JD 摘要、技能差距、优势话术、STAR 素材和反问问题。
- 只在真实发生后记录“已投递、已回复、约面、Offer”等事件。

### 冲刺包与待办

点击顶部“生成今日求职冲刺包”，系统会挑选高潜岗位、补评分、生成准备材料并形成当天行动清单。完成动作后到“待办”标记，不要把未发生的投递或沟通提前记入系统。

### 写入个人看板

配置 `JOB_ONE_STOP_CONTEXT_REPO_PATH` 后，已入库候选卡会出现“写入看板”。点击前会先预览将写入的整行；只有你确认后才会写入个人仓库的收集箱列。系统不会自动移动看板卡片。

## 4. 自动驾驶

自动驾驶适合已经手动验收过一轮的用户。它每天最多扫描一次，复用现有采集漏斗：

```text
定时启动 → 生成搜索词 → 多关键词采集 → 去重/区域过滤 → 分类/评分 → 准备材料 → 待确认
```

### 开启方式

在首页顶部或“设置 → 运行状态”中：

1. 选择“相邻度”：核心 / 相邻 / 探索。
2. 点击“自动驾驶：开”。
3. 每次切换都会重评岗位池和待确认候选，但不会改变岗位状态、看板状态或恢复已排除岗位。

推荐渐进顺序：

```text
手动 + 核心 → 自动驾驶 + 核心 → 自动驾驶 + 相邻 → 观察 7-14 天 → 再考虑探索
```

### 三档求职面

| 档位 | 搜索配额 | 适用场景 |
|---|---:|---|
| 核心 | 核心 100% | 方向刚收敛，先提高命中率 |
| 相邻 | 核心 70% / 相邻 30% | 扩大内容、CMS、B2B 数字营销等相邻岗位 |
| 探索 | 核心 50% / 相邻 30% / 探索 20% | 评估 SaaS 实施、应用支持、客户成功、项目运营等迁移方向 |

相邻度只改变搜索面和岗位族评分，不改变城市、远程、薪资底线、通勤、安全要求、Offer 标准和简历证据边界。纯销售、纯投流、纯社媒等排除项仍然有效。

### 停止方式

随时点击“停止自动化”，或把模式切回“关”。停止只阻止后续定时扫描，不删除已经发现的候选，也不改变已有岗位状态。

## 5. 可选能力

### AI

不配置 AI 也能使用：本地规则、评分和模板仍然有效。需要 AI 时进入“设置 → AI → 添加 Provider”，保存后点击“测试连接”。Key 只写入本机 `.env`，界面不会回显。

### Telegram

配置 Telegram 后，可以把岗位链接、文本或截图发给自己的 bot。机器人只给白名单中的你本人回执；候选仍需在 Web 中确认，不会自动入库。追问使用 `?` 或 `/ask` 开头，多候选时可用 `?2` 指定第二个候选。

## 6. 常见问题

### 扫描发现 0 个岗位

先看通知和“设置 → 采集来源”：

1. OpenCLI 是否安装并登录。
2. `boss_cmd` 是否为当前机器真实路径。
3. 城市和搜索词是否过窄。
4. 是否被区域白名单、硬条件或评分闸门收窄。
5. 查看最近运行详情里的 `skipped` 原因。

### 打开自动驾驶后待确认数量没有增加

先确认当前时间已经到达每日扫描时间，并检查最近一次 BOSS 运行。自动驾驶每天只运行一次；当天已经扫描过，不会因为刷新页面重复扫描。也可以点击“立即扫描”做一次人工补采。

### 为什么相邻岗位没有进入候选

评分闸门在评分后执行。相邻岗位如果没有命中岗位族、命中硬排除项或低于当前分数线，会被拦截并记入运行报告。先切回“核心”或调整本机 `reach.policy`，不要直接把硬条件放宽。

### 需要备份或换机

使用：

```bash
scripts/app.sh backup
```

同时保留 `.env`、`config.yaml`、`data/job_one_stop/` 和个人上下文仓库。换机步骤见 [docs/restore-on-new-machine.md](restore-on-new-machine.md)。

## 7. 安全边界

- 不自动投递。
- 不自动向招聘者发送消息。
- 不破解验证码、风控页或付费墙。
- 不把培训经历包装成正式经验。
- 不会因为开启相邻度而放宽地域、薪资和安全底线。
- 所有自动驾驶结果都必须经过你在 Web 中的最终确认。
